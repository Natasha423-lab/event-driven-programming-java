# 1. SYSTEM OVERVIEW

The Smart Home Controller is an event-driven system designed to allow users to control and monitor different devices within a smart home. The system allows users to switch lights on and off, activate or deactivate security mode, monitor door activity and adjust room temperature.

The system responds to user actions through events. Each event is handled by a specific event handler, which updates the system's state and displays the appropriate feedback to the user.

### Main Objectives

- To demonstrate the use of event sources and event handlers.
- To implement event-driven programming using Java Swing.
- To allow users to interact with different smart home controls.
- To demonstrate how events trigger specific system responses.
- To provide feedback whenever the system's state changes.

---

# 2. EVENT SOURCES

Event sources are the components that generate events when a user interacts with the system.

The Smart Home Controller uses the following event sources:

1. **Lights Toggle Button:** Generates an event when the user switches the lights ON or OFF.
2. **Security Mode Button:** Generates an event when the user activates or deactivates the security system.
3. **Door Control Buttons:** Generate events when the user opens or closes the door.
4. **Temperature Slider:** Generates an event when the user adjusts the desired room temperature.
5. **Reset Button:** Generates an event when the user resets the system to its default settings.

---

# 3. EVENTS TABLE

An event represents an action or occurrence that the system can detect and respond to.

| Event Source | Event Generated | Description |
|---|---|---|
| Lights Toggle Button | `LightsChanged` | Occurs when the user switches the lights ON or OFF. |
| Security Mode Button | `SecurityModeChanged` | Occurs when the security system is activated or deactivated. |
| Door Control Buttons | `DoorOpened` / `DoorClosed` | Occurs when the user opens or closes the door. |
| Temperature Slider | `TemperatureChanged` | Occurs when the user adjusts the room temperature. |
| Reset Button | `SystemReset` | Occurs when the user resets all system settings. |

---

# 4. EVENT HANDLERS TABLE

Event handlers are methods or blocks of code responsible for responding to events generated by event sources.

| Event | Event Handler | System Response |
|---|---|---|
| `LightsChanged` | `handleLightsChanged()` | Updates the lighting status to ON or OFF. |
| `SecurityModeChanged` | `handleSecurityModeChanged()` | Updates the security status to ACTIVE or INACTIVE. |
| `DoorOpened` | `handleDoorOpened()` | Updates the door status and checks whether security mode is active. |
| `DoorClosed` | `handleDoorClosed()` | Updates the door status to CLOSED. |
| `TemperatureChanged` | `handleTemperatureChanged()` | Updates and displays the selected temperature. |
| `SystemReset` | `handleSystemReset()` | Restores all controls and system settings to their default values. |

### Explanation of the Event Flow

1. The system starts and displays the Smart Home Controller interface.
2. The user interacts with one of the available controls.
3. The event source detects the user's action.
4. An event is generated and passed to the appropriate event handler.
5. The event handler processes the event.
6. The system updates its current state.
7. The interface displays feedback to the user.
8. The system waits for another user interaction.

# 6. POTENTIAL ISSUES AND SOLUTIONS

### 6.1 Sensor Failure

A sensor may fail to detect an action or may provide incorrect information to the system.

**Solution:** The system should detect unavailable sensors and notify the user when a sensor is not responding.

### 6.2 False Security Alarms

The security system may incorrectly interpret normal door activity as a security threat.

**Solution:** The system should check whether security mode is active before generating a security alert.

### 6.3 Repeated User Actions

A user may click a button several times, causing repeated events or unnecessary system updates.

**Solution:** The system should check the current state before processing an action to avoid unnecessary changes.

### 6.4 Conflicting Commands

Different commands may attempt to change the same device or system setting.

**Solution:** The system should process events in an organised manner and ensure that the latest valid state is displayed.

### 6.5 System Reset Errors

Resetting the system may leave some controls displaying outdated information.

**Solution:** The reset handler should restore all relevant variables and update the interface to reflect the default settings.

# 7. JAVA SWING PROTOTYPE

The Smart Home Controller prototype is implemented using Java Swing to demonstrate event-driven programming.

### Components Used

- **JFrame:** Creates the main application window.
- **JButton:** Provides interactive controls for lights, security, door operations and resetting the system.
- **JSlider:** Allows users to adjust the desired room temperature.
- **JLabel:** Displays the current status of the smart home devices.
- **JTextArea:** Displays a log of events and system activities.

### Event Handling Implementation

The prototype uses Java event listeners to respond to user interactions.

- `ActionListener` handles button-click events.
- `ChangeListener` handles temperature slider changes.
- `SwingUtilities.invokeLater()` ensures that the graphical user interface is created on the Event Dispatch Thread.

### Features Implemented

1. Switching lights ON and OFF.
2. Activating and deactivating security mode.
3. Opening and closing the door.
4. Adjusting the room temperature.
5. Resetting the system.
6. Displaying system status and an event log.
